# طابور — نظام إدارة التشغيل

> **استمتع باللحظة** — كافتيريا لكل الأوقات

نظام ويب متكامل لإدارة العمليات اليومية لفروع **طابور**: متابعة المهام، التقارير المطلوبة، زيارات الفروع، الحضور، سلامة الغذاء، المبيعات، وتجربة العميل — بواجهة عربية كاملة (RTL) تعمل على الجوال والمتصفح.

**الإصدار الحالي:** v20 · **الحالة:** يعمل في الإنتاج على Netlify

---

## 📋 نظرة عامة

التطبيق يخدم **4 أدوار** بصلاحيات وواجهات مختلفة:

| الدور | النطاق | ما يراه |
|---|---|---|
| **مدير التشغيل** | كل المناطق | كل الصفحات + إدارة النظام + تخصيص القوائم |
| **مدير المنطقة** | منطقته وفروعها | المهام، الزيارات، المرؤوسين، التقارير |
| **مشرف فرع** | فرعه فقط | مهام فرعه، الحضور، سلامة الغذاء، الصيانة |
| **كاشير** | مهامه الشخصية | المهام، التقارير المطلوبة، الدليل التشغيلي |

**التغطية الحالية:** 3 مناطق (ينبع · جدة · الرياض) و10 فروع.

## ✨ الوحدات الرئيسية

### 📊 لوحة التحكم
ملخص يومي بنسبة الإنجاز، وتنبيهات ذكية تظهر تلقائياً (مهام مستعجلة، صيانة معلقة، شكاوى مفتوحة، أو تحذير إذا كان الإنجاز أقل من 50% بعد الساعة 2 ظهراً).

### ✅ مهامي
قائمة مهام يومية مخصصة لكل دور (10–24 مهمة حسب الدور)، مع:
- **4 بطاقات إحصائيات ملوّنة:** منجز · متبقي · متوسط الأسبوع · متوسط الشهر
- **فلاتر تبديل:** الكل / ✅ منجز / ⏳ متبقي
- **رسم بياني أسبوعي** (آخر 7 أيام) و**سجل شهري** بخريطة حرارية (آخر 30 يوم)
- **3 تقارير CSV:** شامل · المنجزة فقط · المتأخرة فقط
- **⚙️ وضع التحرير (مدير التشغيل):** تعديل عنوان أي مهمة — أساسية أو مضافة — وإخفاؤها واستعادتها وإعادة ترتيبها بـ ▲▼
- **⚡ إسناد مهام مستعجلة** لأي شخص أدنى في التسلسل الوظيفي، مع قسمَي «موجهة لي» و«أسندتها للفريق»

### 📑 التقارير المطلوبة
كتالوج التقارير الأسبوعية والشهرية لكل منصب، مع حساب تلقائي لتاريخ الاستحقاق:
- الأسبوعية: كل يوم **سبت**
- الشهرية: يوم **5** من كل شهر
- استثناء: جدول الدوام يوم **20**

يُقرأ من قاعدة البيانات عبر API، ويعمل بنسخة محلية احتياطية عند انقطاع الاتصال. مدير التشغيل يضيف/يعدّل/يحذف من داخل التطبيق.

### 📍 زيارات الفروع
تقييم ميداني من 100 درجة: **النظافة (30) + سير العمل (30) + الكاشير (40)**، مع:
- **متتبع الزيارات الأسبوعية** — 4 زيارات إلزامية مع شريط تقدم و🏆 عند الإكمال
- عرض الفروع المُزارة والمتبقية هذا الأسبوع
- إجراءات تصحيحية وإنذارات مربوطة بالمشرف
- شارة 📅 هذا الأسبوع على الزيارات الحديثة

### 📅 حضور الموظفين
تسجيل حضور بـ **GPS** — يتحقق من وجود الموظف داخل نطاق 1000م من إحداثيات الفرع ويسجّل "حاضر" أو "خارج النطاق" مع المسافة بالمتر.

### 🧪 سلامة الغذاء (HACCP)
8 نقاط فحص يومية: ثلاجة اللحوم والخضار (1–4°م)، الفريزر (−18°م)، حرارة الطبخ (74°م+)، العرض الساخن (63°م+)، نظافة الأسطح، تعقيم الأدوات، غسل اليدين.

### 💰 المبيعات · ⭐ تجربة العميل · 🔧 الصيانة · 📢 التعاميم
متابعة المبيعات اليومية والشهرية لكل فرع، تسجيل الشكاوى ومتابعة حلها، طلبات الصيانة بأولوياتها، والتعاميم الإدارية.

### 📖 الدليل التشغيلي
3 أدلة تدريبية كاملة: **دليل الكاشير** (25 يوم تدريب، سكريبتات، Upselling)، **دليل المشرفين** (الجودة والسلامة والتخزين)، **دليل مدير المنطقة** (بروتوكول الزيارة الميدانية والتقييم).

### ⚙️ إدارة النظام
إدارة المستخدمين والمناطق والفروع، إضافة/تعطيل الحسابات، و**🔧 تخصيص القوائم الرئيسية**:
- تعديل مسمّى أي خانة مباشرة
- إعادة الترتيب بأزرار ▲▼
- تحديد من يرى كل خانة (4 أزرار لكل دور: أخضر ✅ يشوفها / أحمر 🚫 مخفية)

### ⬇️ تصدير التقارير
تصدير CSV بترميز UTF-8 BOM (يفتح مباشرة في Excel العربي) لـ: المهام، الحضور، المستعجلة، الصيانة، الشكاوى، HACCP، الزيارات، وتقرير شامل.

## 🛠 التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة | React 18 (SPA، حزمة إنتاج جاهزة) |
| الاستضافة | Netlify (موقع ثابت — بدون أمر بناء) |
| الـ API | Netlify Functions (`.mts`) |
| قاعدة البيانات | Netlify DB (Postgres) عبر Drizzle ORM |
| الخط | Tajawal (بديل معتمد لـ XB Shafigh) |
| التخزين المحلي | `localStorage` للمهام المضافة وإعدادات القوائم |

### 🎨 الهوية البصرية

```css
:root {
  --tabor-teal:       #80AFB2;  /* الأساسي — الرؤوس والأزرار */
  --tabor-peach:      #FDCABC;  /* التمييز */
  --tabor-gray:       #3D3D3D;  /* النصوص والحدود */
  --tabor-light-teal: #D0E0E0;  /* الخلفيات المساندة */
  --tabor-white:      #FFFFFF;
}
```

تصميم مسطّح، زوايا دائرية، مساحات بيضاء واسعة، واتجاه RTL كامل.

## 🔌 الـ API

```
GET    /api/required-reports        قراءة الكتالوج (يُزرع تلقائياً عند أول تشغيل)
POST   /api/required-reports        إضافة تقرير
PUT    /api/required-reports/:id    تعديل تقرير
DELETE /api/required-reports/:id    حذف تقرير
```

عمليات الكتابة محمية بترويسة `x-tabor-role: ops_manager`.

**جدول `required_reports`:**

| العمود | النوع | الوصف |
|---|---|---|
| `role` | text | `ops_manager` / `area_manager` / `branch_manager` / `cashier` |
| `frequency` | text | `weekly` / `monthly` |
| `title` · `icon` | text | العنوان والأيقونة |
| `due_weekday` | int | يوم الأسبوع (0=الأحد، 6=السبت) — افتراضي 6 |
| `due_day` | int | يوم الشهر — افتراضي 5 |
| `sort_order` · `active` | int · bool | الترتيب والتفعيل |

## 🚀 التشغيل والنشر

المشروع **موقع ثابت** — لا يوجد أمر بناء، ملفات `public/` تُنشر كما هي.

### النشر

```bash
netlify deploy --prod
```

أو ارفع مجلد **`public`** عبر السحب والإفلات في لوحة Netlify → Deploys.

> ⚠️ عند السحب اليدوي، اسحب مجلد `public` نفسه — وليس المجلد الرئيسي.

### تشغيل محلي

```bash
npm install
netlify dev          # يشغّل الموقع + الـ Functions معاً
```

### قاعدة البيانات

```bash
npx drizzle-kit generate    # توليد ترحيل جديد بعد تعديل schema.ts
npx drizzle-kit migrate     # تطبيق الترحيلات
```

## ⚠️ قيود معروفة

1. **المصادقة على العميل** — بيانات الدخول مضمّنة في الحزمة وغير مشفّرة. مناسبة للاستخدام الداخلي الحالي، لكن تحتاج نقلاً لمصادقة على الخادم قبل أي توسّع.
2. **البيانات التشغيلية في الذاكرة** — الزيارات والحضور والشكاوى والمهام اليومية تُحفظ أثناء الجلسة فقط. المستمر حالياً: كتالوج التقارير (قاعدة بيانات)، والمهام المضافة وإعدادات القوائم (`localStorage` لكل جهاز).
3. **الإعدادات غير مشتركة** — المهام المضافة وتعديلاتها وإعدادات القوائم تُحفظ في `localStorage` لكل جهاز على حدة. الحل: نقلها لقاعدة البيانات بنفس نمط `required-reports`.
5. **لا توجد حسابات كاشير** — أضِفها من إدارة النظام ليعمل المستوى الأخير من تسلسل الإسناد.
4. **الكود المصدري غير مرفق** — المستودع يحتوي حزمة الإنتاج فقط دون `src/`. التعديلات تُطبّق عبر `tools/patch-v19.py`. يُفضّل رفع المصدر (`src/App.jsx` + `vite.config`) لتسهيل التطوير.
